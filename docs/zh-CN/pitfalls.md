# 踩坑与修复（每条都来自实机验证）

适用环境：Chrome 154 / macOS / 后台标签。数值为实测值，换版本请重测。

## 1. 后台标签的输入事件 ack 会被无限期拖住（最隐蔽的坑）

**现象**：`Input.dispatchMouseEvent` / `dispatchKeyEvent` 报超时（实测 8 次派发里 4 次 >5s 无响应），
**但事件其实已经送达页面**——probe 里计数器的确递增了。

**后果**：如果把超时当成"失败"去重试，会对同一个元素**点两下**（点赞变取消、提交变重复提交）。

**根因**：未被激活的后台标签处于节流状态，输入事件的 ack 依附于渲染进程的响应，会被无限期推迟。

**修复**：附加标签时施加

```js
await cdp.send('Page.enable', {}, sid);
await cdp.send('Emulation.setFocusEmulationEnabled', { enabled: true }, sid);
await cdp.send('Page.setWebLifecycleState', { state: 'active' }, sid);
```

实测效果（同一标签，施加前 → 施加后）：

| 指标 | 前 | 后 |
|---|---|---|
| `setInterval(16ms)` 1 秒内 | 2 次 | **62~63 次** |
| `requestAnimationFrame` 1 秒内 | **0 次** | **61 次** |
| `Input.dispatchMouseEvent` ack | **超时 >5s** | **8~18ms** |
| `dispatchKeyEvent` / `insertText` | — | 4ms / 1ms |

本技能的 daemon 在 `ensureSession()` 里自动做这件事。
另外 `Page.click` 内置了「真实点击超时 → 回退 DOM 点击」的兜底。

## 2. 后台标签的页面内定时器与动画帧不可用

`setInterval` 被节流到 ~1Hz，`requestAnimationFrame` 完全挂起（实测 1 秒 0 次）。

**所以**：滚动、等待、轮询一律**由 Node 侧驱动**，不要把循环放进页面里。
反例（1.x 的写法）：在页面里 `setInterval(() => window.scrollTo(0, y), 150)` —— 在后台标签上
3 秒只推进 4 次、只滚到 1379px（预期应覆盖 10000px）。

正确写法见 `browser.mjs` 的 `scrollFull()`：Node 循环 + `window.scrollTo` + `sleep`。

## 3. 伪聚焦的副作用：`visibilityState` 恒为 `visible`

施加了第 1 条的修复后，**目标页自己**永远报告 `document.visibilityState === 'visible'`、
`document.hasFocus() === true`，即使它实际上是后台标签。

**所以**：

- 不要用 `visibilityState` 判断「有没有抢用户前台」——它会给出假阴性。
- 但它是个廉价有用的信号：用来确认「激活是否生效」。
- 具体验证方法见 `connect.md` 第 6 节（读 Chrome 活动标签指纹）。
  实测：施加伪聚焦前后、以及静置 25 秒后，用户前台标签指纹始终未变。

个别站点会因为"以为自己在前台"而改变行为（例如自动播放视频）。遇到这种站点用
`CDP_NO_ACTIVATE=1` 关闭激活，并改用 `click(..., {via:'dom'})`。

## 4. `setInputFiles` 是异步的 —— 必须轮询到**服务端产物**

`DOM.setFileInputFiles` 立刻返回，但平台侧上传是异步的。立刻点提交时按钮仍是 `disabled`，
点击**静默无效**。

**修复**：轮询到应用自己给出的确认——预览图变成**服务端地址**（`https://cdn…`），或出现
「已上传 / 重新上传」文案，再提交。

**不要把 `blob:` / `data:` 预览当作成功**（2026-10 修订：本节原文恰好写反了，这条错误建议在一个下午里
造成了两次假阳性）。`URL.createObjectURL` 只证明页面**本地读到了**文件，完全不代表应用收下了它——
React / Next.js 的上传组件经常先出 blob 预览、随后丢弃文件，表单依旧报「该字段未填」。

若始终只有 blob 预览、表单持续提示字段缺失 → 是应用拒收程序化上传，**停止重试**，把**确切文件路径**
交接给用户。

`uploadAndVerify()` 已同步修正：仅出现 blob 预览时视为**尚未上传**。

## 5. 不要用页面文字判断成功

模板里常常常驻"待审核""已结算"这类状态词（在侧边栏/菜单里），
`body.innerText.includes('待审核')` 会给出**假阳性**。

**金标准**：点击提交后 `reload` 详情页，确认提交按钮/表单**消失**。按钮不存在 = 真的提交了。

## 6. `className` 判断开关状态不可靠

SPA 里 `active` / `on` 的语义不一致，甚至有"没有 class 才是开"的反例。

**数字比较法**（`ensureOn()`）：

1. 读点击前的计数 `n1`（元素不存在直接跳过）。
2. 点击，再读 `n2`。
3. `n2 > n1` → 已置为开启，返回 true。
4. `n2 === n1` → 无可观测变化，判定不了，返回 false（**不要**当成成功）。
5. `n2 < n1` → 它本来就是开启态、被这一下点成了关闭 → **补点一次**，再读 `n3`；
   `n3 > n2` 才算恢复成功。

注意第 5 条容易写错：补点后计数只是**回到原值**（`n3 === n1`），
所以判据必须是「相对补点前变大」，而不是「比最初更大」。

## 7. 弹窗/遮罩会吞掉提交点击

radix-ui 一类弹窗带遮罩（`z-50`、`data-state="open"`）盖在提交按钮上，点击被吃掉。

**修复**：先 `dismissModals()` 按安全文案（不再提示/取消/关闭/知道了…）关掉弹窗，再提交；
仍失败就用 DOM 点击绕过指针拦截（`clickByText()` 内置回退）。

## 8. 截图必须真的包含目标内容

整页截图（`captureBeyondViewport`）不会自动解决「内容还没渲染出来」的问题。
先 `scrollFull()` 滚一遍触发懒加载，再把目标节点 `scrollIntoView({block:'center'})` 滚入视口。

另外：**必须验证截图取到的是新帧**（不是缓存/陈旧画面）。廉价判据：
改一次背景色，再截一张，比较两次字节——相同说明帧是陈的。

## 9. 用文本点元素时，别先点到大容器上

`innerText.includes(text)` 会先命中「按钮外层那层 div」（父节点在文档序里更靠前）。
结果点在容器的空白区域，什么都不会发生——而且**不报错**。

**修复**（`clickText()` 的选元素优先级）：精确文本 > 可交互标签（`button/a/[role=button]/...`）
> DOM 更深（更具体）。三者按序打分取最高。

## 10. 一次只处理一个「进行中」的任务

工作流类站点上的常见行为：如果已有一个任务处于未完成状态，再访问「领取 / 新建」入口
会跳回**同一个**任务，而不是给你一个新的。先把当前这个完成或取消，再领取；
任务已经打开时复用它那个详情页，不要另开——另开可能又落到同一个，也可能触发重复提交。

## 11. 短链会跳转，要靠跳转后的域名匹配

分享出来的短链（`bit.ly`、公司自有短域之类）基本都会 302 到主域名。
拿原始短链去匹配标签会找不到——页面提交导航后 `location.href` 已经是跳转后的地址。
要按**跳转后**的域名匹配，或先 `goto()` 并等 URL 稳定下来再取。

顺带一个常见结构差异：评论框往往是 `contenteditable` 而不是 `textarea`。
这类元素的 `value` 恒为空，内容只能从 `innerText` / `textContent` 读；
输入要用 `Input.insertText` 或真实按键，别套用"给 input 赋值"的思路。

## 12. 用标签的 URL 定位，别按顺序猜

标签列表顺序会变（用户随时会新开/关闭标签）。用 URL 子串定位，或对 CLI 用 targetId 前缀。
另外：**同一个 Chrome 上不要同时跑两套 CDP 工具**，会话与授权会互相干扰。

## 13. 交接期间绝对不要点击

人在输密码/扫验证码时，agent 任何一次点击都可能打断输入或误提交。
`waitForHuman()` 的轮询期间只做 `evaluate` 读取——**不点击、不导航、不抢前台**。
同样**不要读 password 字段的值**。

## 14. Chrome 重启后需要重新授权

daemon 检测到 CDP 连接断开就自杀（这是刻意的：避免了连着一个已失效的端点）。
下一条命令会自动拉起新 daemon，届时 Chrome 会再弹一次「允许远程调试」。
不要在用户没同意的情况下用工具自动点掉这个弹窗——那是 Chrome 的安全确认。

## 15. 导航后要校验 URL，不能只看 `readyState`

新建标签后立刻读 `document.readyState`，会读到**初始空白文档**的 `complete`——
看起来"已加载完成"，实际还在 `about:blank`，后面所有读取都拿到空内容。
（真实踩到：`open` 之后第一轮探测得到 `href=about:blank`，误以为导航失败。）

**修复**：判断导航是否成功要看 `location.href` 是否已是目标地址，而不是 `readyState`。
`navigate()`（`goto()`）内部按 readyState 轮询，同样要在调用后复核一次 `page.url()`。

## 16. 现代 React/MUI 后台的数据要显式触发

不少现代后台打开统计页时只有筛选器、**没有结果表**：数据要按下
`APPLY` 之类的按钮才会查询。别把「页面加载完成」当成「数据已就绪」，
要先判断结果区是否真的有内容（例如 `document.body.innerText.length` 是否增长、
或目标表格选择器是否出现），再决定是否点一下查询按钮。

另外这类后台的筛选控件是 MUI 自定义组件（不是原生 `<input type=date>`），
直接改 `value` 不会生效——要走真实点击/输入（本技能的 Input 原语），
或干脆沿用默认范围、在结果里挑出目标那一行（例如按 DATE 分组后取某天那行）。
